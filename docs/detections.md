## R001: Credential stuffing from a single IP

**ATT&CK:** T1110.004 Brute Force - Credential Stuffing  
**Severity:** high  
**Entity:** `ip`

One IP fails logins on many different accounts inside an hour.

**Known false positives:** Carrier-grade NAT or a shared office egress; mitigated by the 75% failure floor.

**Response:** Block the IP for 24 h at the edge and require a CAPTCHA on its next 100 logins.

```sql
SELECT ip AS entity, time_bucket(INTERVAL 1 HOUR, ts) AS window_start,
       time_bucket(INTERVAL 1 HOUR, ts) + INTERVAL 1 HOUR AS window_end,
       list(event_id) AS evidence, count(DISTINCT account_id)::DOUBLE AS metric,
       printf('%d accounts, %.0f%% failed', count(DISTINCT account_id), 100 * avg(CASE WHEN success THEN 0 ELSE 1 END)) AS detail
FROM events WHERE event_type = 'login'
GROUP BY ip, time_bucket(INTERVAL 1 HOUR, ts)
HAVING count(DISTINCT account_id) >= 4 AND avg(CASE WHEN success THEN 0.0 ELSE 1.0 END) >= 0.75
```

## R002: Distributed credential stuffing from one network (ASN)

**ATT&CK:** T1110.004 Brute Force - Credential Stuffing  
**Severity:** high  
**Entity:** `asn`

A botnet rotates IPs to stay under per-IP limits, but its traffic still concentrates in a few networks.

**Known false positives:** A large VPN provider during a regional outage.

**Response:** Step up to CAPTCHA plus email verification for logins from this ASN for 6 h; block the top source IPs.

```sql
SELECT CAST(asn AS VARCHAR) AS entity, time_bucket(INTERVAL 1 HOUR, ts) AS window_start,
       time_bucket(INTERVAL 1 HOUR, ts) + INTERVAL 1 HOUR AS window_end,
       list(event_id) FILTER (WHERE NOT success) AS evidence, count(DISTINCT account_id)::DOUBLE AS metric,
       printf('%d accounts, %d IPs, %.0f%% failed', count(DISTINCT account_id), count(DISTINCT ip), 100 * avg(CASE WHEN success THEN 0 ELSE 1 END)) AS detail
FROM events WHERE event_type = 'login'
GROUP BY asn, time_bucket(INTERVAL 1 HOUR, ts)
HAVING count(DISTINCT account_id) FILTER (WHERE NOT success) >= 25 AND avg(CASE WHEN success THEN 0.0 ELSE 1.0 END) >= 0.7
```

## R003: Password spraying (one password across many accounts)

**ATT&CK:** T1110.003 Brute Force - Password Spraying  
**Severity:** high  
**Entity:** `pw_hash`

The same keyed hash of an attempted password fails on many accounts. Only a 12-character keyed hash is logged, never the password.

**Known false positives:** None expected; legitimate users do not share passwords across accounts.

**Response:** Add the hash to the banned-password list, force reset on any account where it succeeded, and block the source IPs.

```sql
SELECT pw_hash AS entity, time_bucket(INTERVAL 6 HOUR, ts) AS window_start,
       time_bucket(INTERVAL 6 HOUR, ts) + INTERVAL 6 HOUR AS window_end,
       list(event_id) AS evidence, count(DISTINCT account_id)::DOUBLE AS metric,
       printf('%d accounts, %d IPs', count(DISTINCT account_id), count(DISTINCT ip)) AS detail
FROM events WHERE event_type = 'login' AND NOT success AND pw_hash <> ''
GROUP BY pw_hash, time_bucket(INTERVAL 6 HOUR, ts)
HAVING count(DISTINCT account_id) >= 20
```

## R004: Impossible travel on a new device

**ATT&CK:** T1078 Valid Accounts  
**Severity:** low  
**Entity:** `account_id`

Two successful logins imply faster than 900 km/h travel over 1,000+ km, and the second login uses a device fingerprint the account has never used.

**Known false positives:** VPN users; suppressed by requiring a never-seen device fingerprint.

**Response:** Revoke active sessions and require re-authentication with the second factor.

```sql
WITH s AS (
  SELECT event_id, account_id, ts, lat, lon, device_fp,
         lag(ts) OVER w AS pts, lag(lat) OVER w AS plat, lag(lon) OVER w AS plon, lag(event_id) OVER w AS pid,
         count(*) OVER (PARTITION BY account_id, device_fp ORDER BY ts ROWS BETWEEN UNBOUNDED PRECEDING AND 1 PRECEDING) AS fp_seen
  FROM events WHERE event_type = 'login' AND success
  WINDOW w AS (PARTITION BY account_id ORDER BY ts)),
d AS (
  SELECT *, 2 * 6371 * asin(sqrt(pow(sin(radians(lat - plat) / 2), 2) +
            cos(radians(plat)) * cos(radians(lat)) * pow(sin(radians(lon - plon) / 2), 2))) AS km,
         greatest(epoch(ts - pts) / 3600.0, 0.01) AS hrs
  FROM s WHERE pts IS NOT NULL)
SELECT account_id AS entity, pts AS window_start, ts AS window_end, [pid, event_id] AS evidence,
       km / hrs AS metric, printf('%.0f km in %.1f h (%.0f km/h), new device', km, hrs, km / hrs) AS detail
FROM d WHERE km > 1000 AND km / hrs > 900 AND fp_seen = 0
```

## R005: Login from new network and device, then account manipulation

**ATT&CK:** T1098 Account Manipulation  
**Severity:** critical  
**Entity:** `account_id`

A successful login from an ASN and device fingerprint the account has never used is followed within 2 h by an MFA, email or device-pairing change.

**Known false positives:** A user who buys a new phone while travelling and re-pairs a device the same day.

**Response:** Freeze the account, roll back the MFA and email changes, unpair the new device, and notify the user through the original email.

```sql
WITH l AS (
  SELECT event_id, account_id, ts, asn, device_fp,
         count(*) OVER (PARTITION BY account_id, asn ORDER BY ts ROWS BETWEEN UNBOUNDED PRECEDING AND 1 PRECEDING) AS asn_seen,
         count(*) OVER (PARTITION BY account_id, device_fp ORDER BY ts ROWS BETWEEN UNBOUNDED PRECEDING AND 1 PRECEDING) AS fp_seen,
         count(*) OVER (PARTITION BY account_id ORDER BY ts ROWS BETWEEN UNBOUNDED PRECEDING AND 1 PRECEDING) AS prior
  FROM events WHERE event_type = 'login' AND success),
c AS (SELECT event_id, account_id, ts, event_type FROM events
      WHERE event_type IN ('mfa_change', 'email_change', 'device_pair'))
SELECT l.account_id AS entity, l.ts AS window_start, max(c.ts) AS window_end,
       list_prepend(l.event_id, list(c.event_id)) AS evidence, count(*)::DOUBLE AS metric,
       printf('new ASN %d + new device, then %s', l.asn, string_agg(DISTINCT c.event_type, ', ')) AS detail
FROM l JOIN c ON c.account_id = l.account_id AND c.ts BETWEEN l.ts AND l.ts + INTERVAL 2 HOUR
WHERE l.asn_seen = 0 AND l.fp_seen = 0 AND l.prior >= 3
GROUP BY l.account_id, l.ts, l.event_id, l.asn
```

## R006: Cloned device identity

**ATT&CK:** T1036 Masquerading  
**Severity:** high  
**Entity:** `device_id`

One device serial checks in from two or more networks inside 6 h. Home devices check in from one fixed network.

**Known false positives:** A user moving house or an ISP renumbering their block.

**Response:** Rotate the device credential, quarantine check-ins from the new network, and ask the owner to re-pair.

```sql
SELECT device_id AS entity, time_bucket(INTERVAL 6 HOUR, ts) AS window_start,
       time_bucket(INTERVAL 6 HOUR, ts) + INTERVAL 6 HOUR AS window_end,
       list(event_id) AS evidence, count(DISTINCT asn)::DOUBLE AS metric,
       printf('%d networks, %d check-ins', count(DISTINCT asn), count(*)) AS detail
FROM events WHERE event_type = 'device_checkin'
GROUP BY device_id, time_bucket(INTERVAL 6 HOUR, ts)
HAVING count(DISTINCT asn) >= 2
```

## R007: Device ID enumeration through the API

**ATT&CK:** T1087 Account Discovery  
**Severity:** medium  
**Entity:** `account_id`

One account requests many distinct device IDs in 10 minutes and most return 4xx, the signature of walking a sequential ID space.

**Known false positives:** A buggy client retry loop; distinct-ID floor of 50 keeps those out.

**Response:** Revoke the API token, rate-limit the account to 1 request/s, and switch device IDs to unguessable values.

```sql
SELECT account_id AS entity, time_bucket(INTERVAL 10 MINUTE, ts) AS window_start,
       time_bucket(INTERVAL 10 MINUTE, ts) + INTERVAL 10 MINUTE AS window_end,
       list(event_id) AS evidence, count(DISTINCT device_id)::DOUBLE AS metric,
       printf('%d device IDs, %.0f%% 4xx', count(DISTINCT device_id), 100 * avg(CASE WHEN status >= 400 THEN 1 ELSE 0 END)) AS detail
FROM events WHERE event_type = 'api_call'
GROUP BY account_id, time_bucket(INTERVAL 10 MINUTE, ts)
HAVING count(DISTINCT device_id) >= 50 AND avg(CASE WHEN status >= 400 THEN 1.0 ELSE 0.0 END) >= 0.5
```

## R008: Signup burst from one device fingerprint

**ATT&CK:** T1585 Establish Accounts  
**Severity:** medium  
**Entity:** `device_fp`

Five or more new accounts are created from one device fingerprint in 24 h.

**Known false positives:** A family setting up accounts on one shared tablet; usually 2 to 4 accounts.

**Response:** Hold promo payouts for these accounts and require phone verification.

```sql
SELECT device_fp AS entity, time_bucket(INTERVAL 24 HOUR, ts) AS window_start,
       time_bucket(INTERVAL 24 HOUR, ts) + INTERVAL 24 HOUR AS window_end,
       list(event_id) AS evidence, count(*)::DOUBLE AS metric,
       printf('%d signups from one fingerprint', count(*)) AS detail
FROM events WHERE event_type = 'signup'
GROUP BY device_fp, time_bucket(INTERVAL 24 HOUR, ts)
HAVING count(*) >= 5
```

## R009: Spike in failed logins on non-existent usernames

**ATT&CK:** T1110.004 Brute Force - Credential Stuffing  
**Severity:** medium  
**Entity:** `global`

Leaked combo lists contain usernames the service never had. A rise in failures on unknown usernames, over a trailing 7-day hourly baseline, exposes low-and-slow stuffing that per-IP and per-ASN rules miss.

**Known false positives:** An app release that breaks username normalization.

**Response:** Turn on site-wide step-up (CAPTCHA) for logins from never-seen devices until the rate returns to baseline.

```sql
WITH u AS (
  SELECT event_id, ts FROM events
  WHERE event_type = 'login' AND NOT success AND account_id NOT IN (SELECT account_id FROM accounts)),
h AS (SELECT time_bucket(INTERVAL 6 HOUR, ts) AS hr, count(*) AS n, list(event_id) AS ev FROM u GROUP BY 1),
b AS (SELECT hr, n, ev,
             avg(n) OVER (ORDER BY hr RANGE BETWEEN INTERVAL 7 DAY PRECEDING AND INTERVAL 6 HOUR PRECEDING) AS mu,
             stddev_samp(n) OVER (ORDER BY hr RANGE BETWEEN INTERVAL 7 DAY PRECEDING AND INTERVAL 6 HOUR PRECEDING) AS sd
      FROM h)
SELECT 'global' AS entity, hr AS window_start, hr + INTERVAL 6 HOUR AS window_end, ev AS evidence,
       (n - mu) / greatest(sd, 1) AS metric,
       printf('%d unknown-user failures vs baseline %.1f +/- %.1f', n, mu, sd) AS detail
FROM b WHERE mu IS NOT NULL AND n >= mu + 4 * greatest(sd, 1) AND n >= 10
```
